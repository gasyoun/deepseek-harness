# Agent Note: 目标子目标作为独立的持久子列表

Status: implemented

[English](2026-10-24-goal-subgoals.md) | 中文

## 问题

持久化目标过去只携带一个目的、一个阶段和一个轮次计数器。长目标通常由若干可独立核对的条件组成——门禁变绿、变更落地、外部阻塞清除——而目标领域一个都表达不了。模型只有两个糟糕的选择：把条件写进目的文本，那里没有任何重放能把它当作状态；或者只留在自己的推理里，会话恢复后就丢失。用户从另一侧看到同样的缺口：目标条只显示一个阶段，「哪个条件还没完成」除了问模型没有答案。

`complete` 是最尖锐的症状。门禁已绿但变更尚未落地的目标，要么被提前完成（过度声明），要么保持活动却没有留下任何剩余事项的记录。

## 决策

子目标是 `{ id, title, status: open | done | blocked, note? }`。父目标保留自己的目的、阶段、轮次上限、修订号和身份。因此子目标变更不消耗目标修订号，「我的目标视图是否过期」的比较并交换答案仍然只关于目标本身，而不关于它的清单。

### 子目标走自己的事件流

`goal/subgoal` 会话事件携带某个目标变更后的完整列表，以及计算该列表时所依据的修订号。整表事件让重放保持幂等，同时不动严格的 `goal/change` 快照解码器：已发布的 v6 日志仍然有效，并会以空列表重放，因为折叠把 `subgoals` 初始化为 `[]`，且只有创建会重置它。若列表的目标 id 已不再匹配当前目标（目标被清除或被替换），该列表会被丢弃，而不是让重放失败。

### 状态出现在每个消费方本来就在读的地方

`goal` 投影暴露 `subgoals`，其状态版本从 6 移到 7，因此缓存的 v6 投影会被丢弃并重新派生，而不是迁移。模型工具在 `get_goal` 上返回该列表，并在 `update_goal` 上接受 `add_subgoal` / `update_subgoal` / `remove_subgoal`，只用一句简短的提示说明按条件拆分与完成门槛——保持简短的原因是录制的压缩夹具带有 token 预算，过长的段落会越界；`add_subgoal` 把子目标创建为 `open`，并在传入状态或备注时拒绝并提示改用 `update_subgoal`（一次真实 GUI 运行发现模型向 `add_subgoal` 传了 `subgoal_status`，最初的实现会静默忽略它）；`/goal` 渲染 `Subgoals: N/M done` 并为每个子目标列出一行；Web 目标条显示一个 `done/total` 徽标，在原位展开清单。

### 边界与完成规则在变更发生处强制执行

一个目标最多携带 16 个子目标，标题最多 160 字符，备注最多 500。服务自行铸造 id（`s1`、`s2`……），因此客户端无法与另一个子目标冲突或伪造。只要还有子目标不是 `done`，`complete` 就会被拒绝，错误会点名未完成的 id 及其状态；把子目标标为 `blocked` 是表达「该条件暂时无法关闭」的持久方式，同时保持目标本身处于活动状态。

## 备选方案

- **把条件放进目的文本。** 拒绝：文本不会作为状态重放，无法回答「哪一条还没完成」，也无法为完成把关。
- **把每个条件升级为自己的目标。** 拒绝：服务按设计每个会话只保留一个当前目标，这样做要么制造多个会话，要么丢失共享的轮次预算与目的。
- **用子列表扩展 `goal/change`。** 拒绝：快照解码器为每个阶段校验确切的键集合，放宽它会破坏已发布的日志与严格重放承诺，而该能力并不需要共享目标的比较并交换修订号。
- **不升版本地改变投影。** 拒绝：缓存的 v6 行会无法通过新的状态模式；升版本让注册表丢弃旧行并重新派生。

## 后果

- 恢复或 fork 的会话会像重放目标一样重放它的子目标；没有新的存储、文件或迁移。
- 既有目标测试与投影夹具相应改出了 `subgoals: []` 预期——折叠现在总是报告该列表，对无目标的会话而言这是诚实的值。
- Web 目标条在折叠时仍只有一行；清单是展开式披露，不是新面板。
- 本次变更仍欠 Web 端到端录制输出：该通道需要 Playwright 浏览器，而实现环境无法安装；包级 README 对照版本已随本变更提供。
